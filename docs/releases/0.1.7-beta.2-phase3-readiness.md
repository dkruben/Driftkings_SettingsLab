- `mod/res/scripts/client/driftkings/gameface/core.py`: `attach_assets()` and its `from openwg_gameface import gf_mod_inject` import removed. `payload_model()` delegates to `native_payload_model()`, which accepts only native transports.
  - Trace: all 21 `payload_model()` callers resolve to `native_document` or to the owned window. No caller reached the OpenWG branch. The battle-context catalog entries (9) are all `own_window`.
- `mod/res/scripts/client/driftkings/gameface/battle/common.py`: a battle card whose catalog transport is not `own_window` now raises `ValueError`. The OpenWG child hook (`_getChildComponents` with `gf_mod_inject`) was removed; it had no remaining consumer.
- `mod/res/scripts/client/driftkings/core/battle_capabilities.py`: `supports_gameface_overlay()` removed. It gated on `openwg_gameface` presence and had no callers.
- `build_tools/generate_ui_catalog.py`: the implicit `'openwg'` transport default is removed. Owned features must declare a native transport; features without an owner declare none. The catalog generator reports `injected: 0, native: 20`.
- `mod/res/scripts/client/driftkings/core/mod_compatibility.py` is kept. It is a passive observer that names ModsListAPI and OpenWG to report third-party presence and never imports them. This is the optional interoperability mechanism.
- Retained by design: `mod/res/gui/gameface/mods/driftkings/shared/bootstrap.js` is still packaged. Its generated `features` block is now `{}` and nothing loads through it. **Dead code: remove after the NA runtime test.**
