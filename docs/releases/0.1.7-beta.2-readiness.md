## Production build contract

The compiler separates game version, pinned source client (realm, build, revision and snapshot), package channel and mode. A profile ties the source to reference file digests, production patch descriptors, a marker lock, Flash libraries and evidence files for the intended runtime realms. Build reports record the source client and the runtime realm scope. Setup and publication recheck that scope. A profile may cover additional production realms once their resources are verified. CT uses the existing reference checks and is eligible for development builds. The validation record for 2.4.2.0 includes CN and this global beta requires all four realms. Stable publication remains governed by the existing promotion workflow, signed manifest, checksums and environment approval.

For a candidate preflight, point the compiler at the read-only production client and matching source. An isolated debug run keeps locally generated files in an experiment directory. After resource pins are reviewed, follow the existing release instructions for Setup, checksums and offline signing. See [build and release instructions](../../CONTRIBUTING.md) and [promotion](README.md).

The updater continues to enforce version, channel, game version, size, signature and package SHA-256. Preserve `mods/configs/driftkings` during updates. Defaults use missing-only installation. Historical `removeFog` values are inert and remain in existing profiles. Any previously installed standalone Remove Fog package remains on disk until the user removes it with the game closed.

## Fair Play review

The candidate omits the Remove Fog control, runtime scheduler and installer helper. The research sources and historical notes remain available in the repository. The old preference cannot schedule installation on startup, profile reload or restart in the candidate. A pre-existing standalone package requires separate manual removal for a clean test.

The source check found these items for explicit owner review.

- `minimap_plugins.py` retains last-known enemy markers on the minimap and applies an own-gun sector setting. Verify mode restrictions and check that no enemy gun direction or world-space last-known marker is presented.
- `autoaim_target_indicator.py` reads the client's existing `autoAimVehicle` and checks that it is in the world, visible and alive. `enemy_spotting_status.py` formats the client battle-feedback stream. Validate loss-of-visibility and teardown in game.
- `penetration_indicator.py` reads gun-marker collision and computes armour estimates. Check camera/range behaviour and interaction with the native Armor Flashlight, with particular attention to the official prohibition on altering Armor Flashlight functionality.
- `repair_controls.py` dispatches through explicit key-down handlers. `repairAll()` may use several consumables based on a single key press, selecting damaged modules or crew from configured priorities. Review that behaviour against the automatic consumables restriction. Verify the consent flow for Tour Coins. Fair Play is a publication checkpoint for the project owner. See [Wargaming's prohibited mods policy](https://worldoftanks.eu/en/content/guide/fair-play/prohibited-mods/).

## In-game acceptance

1. Identify the production candidate by SHA-256 and record the game realm, build and full mod/dependency list. Test NA, EU, ASIA and CN within the advertised scope. CT is a development reference.
2. Run a clean install and a rehearsal upgrading a copied 0.1.6 profile. Verify the requested settings, account protections, updater, absent fog control and no new fog package. Verify that a legacy true value leaves user data intact.
3. Check launch/exit, Settings Panel, launcher, carousel, crew screens, clock across hangars, BattleInfo, marker and consumable layouts, two consecutive battles, replay and CN localization. Record features exercised, logs, known limitations and lifecycle behaviour.
4. Verify the package inventory, protected dependency hashes, Setup acceptance from each supported realm, signed-update integrity, and SHA-256 for all distribution assets. Use the existing promotion flow once the beta is approved.
